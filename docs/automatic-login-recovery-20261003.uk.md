# Автоматичне відновлення тимчасових відмов MT5

Після нічної відмови Exness журнал містив точне `Service is not available`, але рахунок отримав AUTH_FAILED і PAUSED. Ручна повторна задача успішно підключила той самий рахунок з тими самими реквізитами. Чому саме ранкова спроба не прочитала повний запис, не встановлено; під час перевірки відтворено дефект класифікації частково записаного рядка.

Виправлення worker:

- Читає лише завершені рядки журналу; неповний UTF-16 символ або частину повідомлення не сприймає як явну відмову авторизації.
- Чекає появи свіжого запису до 10 секунд замість 3. Тимчасову помилку читання перечитує в межах цього строку.
- Точний свіжий `Service is not available` для потрібних рахунку/сервера залишається NETWORK_UNAVAILABLE. Чинна durable черга API автоматично повторює спроби з backoff приблизно 30 с, 60 с, 120 с і далі до 15 хвилин плюс jitter до 10 с. Успішне завершення скидає failureCount і повертає штатний імпорт.
- Нативний -6 без підтвердженої явної відмови стає CONNECTION_FAILED. Чинна політика API допускає дві додаткові спроби, після третьої невдалої — PAUSED.
- Повний свіжий запис відмови, зокрема Invalid account, має пріоритет і залишається AUTH_FAILED без автоматичного нескінченного перебору.
- Ротація/завеликий журнал не дозволяють використовувати старі записи як доказ. Результат залишається неоднозначним із лише обмеженими повторами.
- Перевірки рахунку, сервера, процесу, investor mode/згоди власника і вимкнення Python trading не послаблені. До успішного входу дані не читаються. Реквізити не змінюються.

Зміна не скидає довільні історичні PAUSED-записи, не змінює API/схему БД і не потребує автоматизації Codex: повтори виконує постійна production-черга.

Перевірка: 200 Python unittest, включно з частковим UTF-16/рядком, flush пізніше старого дедлайну, тимчасовою помилкою читання, пріоритетом Invalid account та забороною читати кешовані дані після невдалого входу. Чинна зібрана API retry-policy окремо перевірена локальним запуском на кодах NETWORK_UNAVAILABLE, CONNECTION_FAILED, AUTH_FAILED, IDENTITY_DRIFT, TRADING_ENABLED. Жодних навмисних помилок у реальні підключення не ін'єктували.
