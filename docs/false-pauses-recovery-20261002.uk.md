# Відновлення MT5 після хибних пауз — 2026-10-02

## Причини та зміни

- FundingPips-SIM1 `20451593`: попередній `AUTH_FAILED` збігся із записами
  `error sending synchronization command` / `failed (Common error)` і наступним
  успішним входом у журналі термінала. Одноразове читання журналу могло випередити
  його запис. Worker тепер очікує до 3 секунд появи точної свіжої пари повідомлень
  для цього логіна й сервера. Лише ця пара дозволяє `NETWORK_UNAVAILABLE`.
  Явна відмова на кшталт `Invalid account` має пріоритет. Код native-помилки
  зчитується один раз до очікування; невдалий вхід не дозволяє читати історію.
- MetaQuotes-Demo `112447298` і FundingPips-SIM1 `20892864`: раніше
  `INVESTOR_UNVERIFIED` одразу зупиняв завдання, хоча журнал показував investor mode.
  API тепер дозволяє дві повторні спроби з наявною затримкою та jitter. Третя
  послідовна невдача зупиняє завдання. Кожна спроба заново проходить незмінені
  перевірки identity, режиму читання та заборони Python trading. Журнал не замінює
  підтвердження режиму читання і не дозволяє обійти перевірку вікна.

## Точкове відновлення

У чергу повернено лише три явно запитані завдання. SQL перевіряв PAUSED,
failureCount, fence, версію credentials, очікуваний код помилки, enabled,
наявність зашифрованого пароля та відсутність lease/slot. Паролі, consent,
історію й часову політику не змінювали. Помилки та лічильники скидає лише
успішний імпорт.

- `20451593`: імпорт відновився; станом на 09:55 UTC fence зріс з 14341 до
  14353, останній збір та імпорт 09:55:04.538 UTC, помилок немає.
- `112447298`: імпорт відновився; fence зріс з 7468 до 7479, останній збір та
  імпорт 09:54:44.568 UTC, помилок немає.
- `20892864`: повторний вхід о 09:48:01.970 UTC у demo-02 отримав точну відповідь
  `authorization on FundingPips-SIM1 failed (Invalid account)`. Залишено PAUSED /
  AUTH_FAILED. Потрібно перевірити login/server/password у брокера. Цей код не
  доводить suspension і не дозволяє безпечно автоматично відновити доступ.
