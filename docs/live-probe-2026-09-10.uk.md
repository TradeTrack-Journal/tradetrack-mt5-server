**Локальна перевірка деморахунку — 10 вересня 2026**

**Уточнення після перевірки історії:** цей рахунок має дві закриті угоди, разом 84.45 USD. Початкова UTC-межа помилково виключала broker-time records. На вже відкритому MT5 виправлена проба повернула п'ять raw records. Детальний доказ і поточні обмеження — [звіт про часовий діапазон та attach](history-clock-and-attach-2026-09-10.uk.md). Нижче збережені початкові спостереження, а не висновок про відсутність історії.

**Результат:** Python успішно авторизував наданий користувачем деморахунок MetaQuotes-Demo і виконав три читання історії та відкритих позицій. Login/server і portable path/data_path збіглися з очікуваними. У журналі цієї тестової копії є авторизація на MetaQuotes-Demo, синхронізація та явні повідомлення `trading has been disabled - investor mode` і `balance management has been disabled - investor mode`.

Ідентифікатор рахунку, пароль та фінансові records не збережені в цьому звіті. Торгові методи не викликалися. Пароль передавався через приховане введення та stdin, не через CLI, git або INI. Термінал може створювати accounts.dat навіть із вимкненим Save password, тому каталог тестового slot слід вважати чутливим і прибирати після діагностики.

**Що виявив холодний запуск**

Три прогони на чистих копіях завершилися на initialize з `-10005` (IPC timeout). Заміна пакета 5.0.5640 на 5.0.6180 сама по собі не усунула помилку. На початку копії без MetaEditor також писали попередження Compiler. Після додавання MetaEditor та metatester у чистий slot попередження замінилося повною компіляцією вбудованих MQL5-файлів.

В одному спостереженому запуску компіляція тривала приблизно 79 секунд, що значно більше за 20-секундний initialize timeout проби. Після виходу з початкового Login-діалогу та завершення фонового запуску журнал зафіксував авторизацію, а наступний Python-прогін пройшов. Це вказує на необхідність окремого provisioning/readiness перед синком; конкретну причинність таймаутів ще треба підтвердити повторним автоматичним холодним запуском.

Термінал також відкривав Login-діалог. Один допоміжний діагностичний експеримент з Win32-введенням дав пошкоджені символи через некоректний час життя буфера рядка; його припинено, діалог закрито. Цей GUI-спосіб не входить у код collector або проби. Успішний фінальний прогін передав credentials безпосередньо Python API.

Нові builds запускають локальний MCP listener. При одночасному основному терміналі журнал копії містив конфлікт 127.0.0.1:22346; пізніше listener зміг запуститися. Не доведено, що цей конфлікт спричинив IPC timeout. Для пулу потрібна перевірена конфігурація вимкнення непотрібного MCP/AI або окремих портів. Не підключати collector до MCP сусіднього slot.

**Що реалізовано і як повторити**

`scripts/probe_mt5.py` — дослідна локальна проба: копіює статичні компоненти й broker catalogue у власний ACL-обмежений каталог, запускає власний terminal process, отримує пароль без echo, передає його child через stdin, обмежує child 75 секундами, перевіряє identity/path, повертає агрегати й завершує свій термінал. Чистий запуск ще може закінчитися timeout; це не готовий production session manager. Діалог термінала може з'являтися попри прихований запуск Windows.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-probe.txt
.\.venv\Scripts\python.exe -m scripts.probe_mt5 --source "C:\Program Files\MetaTrader 5\terminal64.exe" --login YOUR_DEMO_LOGIN --server MetaQuotes-Demo
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Пароль вводиться після запуску; параметра `--password` немає. Не використовувати цей дослідний інструмент для production credentials. Власні runtime-каталоги інструмент залишає поза git для дослідження; після перевірки треба завершити їхні процеси й видалити саме ці каталоги. Процеси поточної перевірки завершені. Автоматична перевірка команд заблокувала рекурсивне видалення трьох runtime-каталогів без детального пояснення; вужче видалення файлів `Config/accounts.dat` дозволене й виконане. Решта артефактів залишається в ACL-обмеженому `%LOCALAPPDATA%\TradeTrack\local-probes` (папки `mt5-5acln942`, `mt5-e6zstn_t`, `mt5-28imoskr`). Це не доказ відсутності будь-яких інших кешованих даних у терміналі.

34 автоматичні тести пройшли: 24 для raw data core та 10 для fail-safe діагностики — неправильний server/path, failed explicit login без читання cached account, зміна identity після читання, None-відповіді, приховування native error text і гарантований shutdown. Native MT5 у цих тестах замінений контрольованим fake; це доповнення до описаної живої перевірки, не її заміна.

**Наступні критерії етапу B**

1. Окремий bounded bootstrap для нового slot, readiness після компіляції та broker provisioning; повторити cold start без втручання в GUI.
2. Налаштувати й перевіряти `tradeapi_disabled=True` як додатковий захист до investor-only.
3. Побудувати fail-closed investor verifier для свіжої login-спроби. Рядок поточного журналу підтверджує конкретний демотест, але не сертифікує універсальний parser. Невідомий або stale доказ має відхилятися.
4. Перевірити відмову неправильного пароля на живому demo без повернення даних старої сесії; unit test уже є. Відомий master-пароль іншого спеціального demo може знадобитися для негативної перевірки режиму, але production master не потрібний.
5. Перевірити дані на деморахунку з угодами, потім restart і 2–3 одночасні slots. Лише після цього підключати нове ядро до job transport.
