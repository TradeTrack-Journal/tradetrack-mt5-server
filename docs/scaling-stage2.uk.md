# MT5: черга та навантаження, 2026-10-01

## Реалізовано

- Черга API допускає два початкові імпорти загалом та один на власника.
  Кількість підключених рахунків користувача не обмежувалася.
- Вибір наступного завдання враховує останнє обслуговування власника.
- Результати різних слотів більше не вимагають ексклюзивного блокування вузла.
- Щільні початкові та поточні історії читаються пакетами. Для поточної історії
  сервер зберігає наступну верхню межу та нижню межу проходу в raw snapshot.
  Повторний запит після перезапуску продовжує прохід; межі перевіряються разом
  із lease/fence. Значення часу залишаються broker-reported.
- Незмінні raw deals не перезаписуються. Непотрібний повний перерахунок журналу
  пропускається за контрольними сумами версій рядків; повна звірка — щогодини.
- Важкий перерахунок журналу виконується один за раз, записи створюються
  пакетним SQL. Чужі нотатки й ручні поля не перезаписуються.
- Ключ шифрування кешується після derivation, без зміни формату шифрування;
  заміна ENCRYPTION_KEY інвалідує кеш.

## Перевірка

158 Python-перевірок успішні; lint/build API та його локальні health endpoints
успішні. Наявний collector lifecycle script пройшов на локальному PostgreSQL.
Старий journal selftest несумісний із поточним create flow та завершився
COLLECTOR_SERVER_UNRESOLVED; його не зараховано як успішний.

Окремий локальний вимір: 100 синтетичних підключень, 5 синтетичних слотів,
60 початкових підключень і 40 регулярних. Черга обробила всі 100; максимум два
початкові завдання та одне на власника. Перевірено повторний ACK, відновлення
двосторінкового проходу новим екземпляром сервісу і виправлення raw payload
без зміни observedAt. Реальні брокери в цій перевірці не використовувалися.

| Raw deals | Повний імпорт | Без змін |
| --- | ---: | ---: |
| 1 000 | 208 мс | 11 мс |
| 10 000 | 2 876 мс | 36 мс |
| 50 000 | 7 781 мс | 140 мс |

До оптимізації сценарій 50 000 перевищував 15-секундний тайм-аут транзакції.
V8 heap тестового процесу обмежено 256 MiB, його RSS досягав 430 MiB.
Сценарій та журнал вимірювання збережені локально в
C:/TradeTrack/worker/demo-backend/benchmark-phase2.cjs та
C:/TradeTrack/worker/demo-backend/benchmark-phase2-result.log.

## Межі та розгортання

Залишаємо п'ять терміналів та один VPS. Ці результати не доводять, що сто
реальних MT5-акаунтів оновлюватимуться щохвилини: брокерські затримки, Windows UI,
мережа Fly—Neon і паралельні інтеграції тут не відтворені. Зокрема, під час роботи
спостерігалися тимчасові UI_DIALOG_UNAVAILABLE/TERMINAL_CHANGED; збір відновився.

Збережено захисні межі 50 000 рядків журналу та 5 000 deals+positions у пакеті.
Інтервал з понад 4 000 deals у мінімальній секунді вимагає іншого протоколу.
Збільшувати кількість терміналів до реального навантажувального виміру не варто.

Порядок: спочатку API, потім immutable release воркера. Для перемикання
створити worker.drain, дочекатися виходу поточного контролера/дітей, змінити
шлях Start-Worker.ps1 та прибрати drain. Supervisor запускає новий контролер.
При відкаті воркера враховувати незавершені recent cursors: старий воркер їх
не підтримує; не видаляти курсори чи raw evidence вручну.
