# Зміст MT5 API-помилок у діагностиці

HTTP 409 від TradeTrack API — конфлікт стану, а не самостійний доказ відхилення MT5-пароля. Причини в API включають SESSION_CHANGED, LEASE_LOST, SLOT_BUSY, REPORT_OUT_OF_ORDER, RESULT_CONFLICT тощо. CREDENTIALS_REVOKED стосується поточної авторизації/версії реквізитів у TradeTrack, а не перевірки пароля брокером. Для MT5-відмови існує AUTH_FAILED; вона теж не відрізняє сама по собі неправильні реквізити від обмежень рахунку брокером.

Попередня реалізація відкидала HTTP response body, а Sentry before_send залишав лише загальний код та слот. Причину старої події, якщо її окремо не записали в іншому джерелі, відновити неможливо. Локальний журнал 2026-10-02 містить останній API_HTTP_409 о 14:18:27 UTC під час розгортання каталогів; жодного точного підкоду в ньому немає.

Зміни:

- HTTP error body читається з межею 4096 байтів. З нього приймається тільки точний `message` із закритого словника API-кодів; довільний текст, HTML, масиви та завеликі відповіді відкидаються.
- AgentError зберігає allowlisted operation і apiReason. Загальний код залишається незмінним для логіки повторів/відновлення.
- Планувальник і watchdog передають ці поля в JSONL та telemetry. Before-send повторно фільтрує їх.
- Sentry logentry містить зрозуміле фіксоване пояснення; теги містять операцію/підкод, контекст — їх пояснення. Fingerprint та ліміти шуму залишилися за основним кодом, нових повідомлень на кожен підкод не створюється.
- Сирі native MT5-повідомлення, account IDs, логіни, URL задач, реквізити, токени та торгові дані не передаються. Для основних UI/network/identity/MT5-кодів додано безпечні фіксовані пояснення.

196 unittest пройшли: обмежене читання, вилучення приватних даних, проходження контексту через планувальник і Sentry sanitizer, незмінність debounce. Додатково реальний Sentry SDK серіалізував подію в локальний OfflineTransport без мережевого надсилання: `logentry` і контекст збережені, маркер приватного поля відсутній. Доставка нових подій у production Sentry окремо не перевірялася; тестового спаму не надсилали.
